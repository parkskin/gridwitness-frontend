# GridWitness Frontend

전력 고장파형 분석과 모형 실측을 연결하는 React·TypeScript 웹입니다. **모형의 직류 계측, 공개 교류 파형, 한전 사용량 자료는 별도의 용도로 다룹니다.**

```bash
npm ci
npm test
npm run dev
npm run build
npm run lint
```

Chrome/Edge에서 우노를 연결할 수 있습니다. 처음에는 실측 장치 미연결 상태이며, 시뮬레이터는 사용자가 직접 선택합니다.

## 화면과 흐름

| 화면 | 주소 | 내용 |
|---|---|---|
| 소개 | `/` | 서비스 설명과 공개 파형 샘플 |
| 대시보드 | `/dashboard` | 계측·사건·검토 현황 |
| 마을 | `/village`, `/village/loads` | 3D 모형, 채널 제어·점검·기준표 |
| FRTU | `/frtu`, `/live` | 실측 추이, 원시 사건 파형·판정·근거 |
| 사건 기록 | `/cases`, `/cases/new`, `/cases/:id` | 등록 → 입력 검사 → 분류/보류 → 근거 → 사람 검토 |
| 현장 AI | `/field/:id` | 사건 근거를 사용하는 글·음성 질문, 현장 메모 |

## 실제 모형

- 우노 스케치: `arduino/gridwitness_village/gridwitness_village.ino` v3.1.
- USB 직렬 115200 baud, 계측은 0.5초 간격. 사건은 10ms 간격 260점(발생 전60·후200)입니다.
- 설계는 INA219 0x40(주택)·0x41(가로등) 두 개입니다. 하나만 감지되면 전체 계측만 사용하며 분기값을 만들지 않습니다.
- LED5개를 채널 릴레이로 제어합니다. 채널1=D3 주택1, 채널2=D4 주택3, 채널3=D5 주택2, 채널4/5=D6/D7 가로등1/2입니다.
- `RELAY 0/1`은 전체 차단/복구, `CH 3 0/1`은 주택2 끄기/켜기입니다. 장치 응답이 와야 명령이 확인됩니다.
- 센서 오류값을 0V로 변환하지 않습니다. 데이터 없음·연결 끊김은 실제 0V 계측과 구분합니다.
- LED 전류는 부품·배선·전압에 따라 다르며 고정 56mA로 판단하지 않습니다. 조합별 실측 정상 전류표와 채널 점검을 사용합니다.

처음 연결할 때 **설정 → 실측 장치 → Arduino Uno 포트 선택**을 누릅니다. 이미 허용한 장치는 자동 재연결할 수 있습니다. 같은 COM포트는 다른 프로그램과 동시에 열 수 없습니다.

## 분석 모델과 대화

| 모델 | 입력 계약 | 결과 |
|---|---|---|
| 중국 Xiong | 1312×7, 4096Hz, 50Hz, Ia/Ib/Ic/In/Va/Vb/Vc | SIF·MIF·PF·TD 또는 보류 |
| 러시아 OscGrid | 512×5, 1600Hz, 50Hz, Ia/Ic/Va/Vb/Vc | 정상·개폐·이상·사고 또는 보류 |

실제 서버에 어떤 모델이 준비됐는지는 **설정 → LLM·분석기 연결 상태**에서 확인합니다. 데이터셋으로 나라를 정하며 다른 모델로 임의 대체하지 않습니다. COMTRADE는 실제 있는 지원 채널을 읽고, 없는 채널을 임의로 합성하지 않습니다. 국내 실제 배전 성능 검증을 뜻하지 않으며 점수는 정답 확률이 아닙니다.

현장 대화는 서버의 사건 근거를 사용합니다. LLM을 설정하면 근거 선택을 맡기고, 기록에 없는 사실은 생성하지 않습니다. 설비 조작은 거절하고 근거 없는 위치·물리적 원인은 보류합니다. 답변의 **LLM / 서버 규칙 / 브라우저 기록**과 모델·대체 사유를 표시합니다. 마을 상태 도우미는 별도 규칙 조회 기능입니다.

LLM은 API 서버의 `GW_ASSISTANT_LLM_URL`, `GW_ASSISTANT_MODEL`로 연결합니다. `GW_ASSISTANT_TIMEOUT_SECONDS`로 유한 응답 시간을 정합니다. 모델 준비 상태와 실제 채택 응답을 함께 확인해야 연결 검증이 완료됩니다.

설정 화면의 LLM 상태는 서버 모델 목록에 설정 모델이 보이는지 확인한 결과입니다. 실제 답변 생성 성공을 뜻하지 않으며, 각 대화 응답의 `answer_mode`, `llm_model`, 대체 사유를 확인합니다.

## 저장과 서버

기본 API는 `https://gridwitness-api.https.gsmsv.site`입니다. 개발 서버·Vercel은 `/gw-api`로 프록시하고 GitHub Pages는 API를 직접 호출합니다. 로컬 API를 쓰려면 Vite 시작 전 `GW_API_TARGET`을 설정하거나 설정 화면에서 주소를 바꿉니다. 하위 경로 빌드는 `VITE_BASE=/gridwitness-frontend/`를 사용합니다.

- 교류 사건의 원본·진단·분석·검토·감사 기록은 서버에서 다시 불러옵니다. 캐시는 서버 주소별로 분리합니다.
- 마을 원시 파형·판정·실시간 사건·등록한 IoT 사건은 `/api/v1/village/records`에 UUID로 보존합니다. 서버 전송 실패는 브라우저의 재전송 대기 큐에 남기며 저장 상태를 표시합니다.
- 현장 대화와 메모도 서버 저장을 우선하며 장애 때의 로컬 기록을 보존합니다. 대화 초기화는 기존 기록을 보관하고 새 대화를 시작합니다.
- 전체 내보내기는 서버 기록과 원본을 확인합니다. 전부 받지 못한 결과를 완전한 백업으로 표시하지 않습니다.
- 서버가 `GW_API_TOKEN`을 설정한 경우 설정 화면에서 접근 코드를 입력합니다. 미설정이면 공개 시연 모드이며 작업자 이름은 로그인 신원을 대신하지 않습니다.
- 학교 서버 만료 예정일은 2026-11-20입니다. 운영 백업과 이전은 별도로 관리해야 합니다.

UI 설명은 `docs/사용설명서.md`, 구현 설명은 `docs/로직-사용설명서.md`, 전체 점검 결과는 `docs/프로그램_전체점검_2026-11-10.md`를 참고합니다.
